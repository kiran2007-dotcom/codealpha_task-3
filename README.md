# ConnectSphere

ConnectSphere is a full-stack social networking web application built with **React**, **TypeScript**, **Tailwind CSS**, **Node.js (Express)**, **Firebase Authentication**, **Cloud Firestore**, and **Firebase Storage**.

---

## Key Features

- **User Authentication & Verification**: Email/password registration and login with strong password validation, Google Sign-In (`signInWithPopup`), email verification enforcement, persistent sessions, and protected workspace routes.
- **User Profiles**: Unique usernames reserved atomically via `/usernames/{usernameLower}`, profile pictures, cover images, full name, biography, location, joined date, live post/follower/following counters, and Grid/List post views. Users can only edit their own profiles.
- **Home Feed & Bookmarks**: Create text and photo posts with `#hashtags`, edit and delete own posts, switch between `All posts` and `Following` feeds, bookmark posts (`Bookmarks` tab), paginate / infinite-scroll posts, and open individual post threads.
- **24-Hour Stories**: Horizontal Stories tray above the feed with story image uploads, auto-advancing progress bars, time-remaining badges, 24-hour expiration filtering, and a live Story Viewers list.
- **Likes & Comments**: Deterministic like tracking (`{postId}_{userId}`) preventing duplicate likes, real-time comment threads with create, edit, and delete support for comment authors.
- **Follow System**: Follow/unfollow users, prevent self-following and duplicate follow edges, view followers and following lists, and filter the home feed to followed creators.
- **Explore & Discovery**: Responsive Explore image grid, live search across users, posts, and `#hashtags`, real suggested users, and trending hashtags/posts ranked strictly by real data.
- **Real-Time Notifications**: Generated by actual follow, like, comment, and direct message events with unread counters, read/unread states, and click-through navigation.
- **Direct Messaging**: Private one-to-one conversations with real-time message delivery, unread indicators, and security rules ensuring only conversation participants can read or send messages.
- **Light & Dark Theme**: Accessible Light and Dark themes persisted per browser via `ThemeContext`.

## Installation Instructions

1. **Install dependencies**
   ```bash
   npm install
   ```

2. **Configure environment variables**
   Copy `.env.example` to `.env` if running locally outside AI Studio and configure any optional environment values.

3. **Run development server**
   ```bash
   npm run dev
   ```
   The Node.js Express + Vite server listens on `http://localhost:3000`.

4. **Build and run in production**
   ```bash
   npm run build
   npm start
   ```

5. **Lint TypeScript & Firestore security rules**
   ```bash
   npm run lint
   npx eslint firestore.rules
   ```

## Firebase Configuration

ConnectSphere loads its Firebase configuration from `firebase-applet-config.json` (`projectId`, `appId`, `apiKey`, `authDomain`, `firestoreDatabaseId`, `storageBucket`).

- **Google Sign-In**: Enabled out of the box via AI Studio Firebase provisioning.
- **Email/Password Authentication**: Supported in `AuthScreen.tsx`. To use Email/Password registration in your Firebase project, verify that **Email/Password** is enabled in Firebase Console under **Authentication → Sign-in method**.
- **Media Storage**: Uploads first target **Firebase Storage** (`avatars/`, `covers/`, `posts/`) and automatically fall back to the authenticated Node.js backend (`POST /api/upload` with Firebase ID token verification) if Storage bucket permissions are not yet enabled.

## Database Structure

All collections are formally specified in `firebase-blueprint.json`:

| Collection Path | Purpose | Key Fields |
|---|---|---|
| `/users/{userId}` | Public user profiles (zero PII) | `uid`, `username`, `fullName`, `bio`, `location`, `avatarUrl`, `coverUrl`, `postsCount`, `followersCount`, `followingCount`, `isPublic`, `joinedAt`, `updatedAt` |
| `/users/{userId}/private/{docId}` | Isolated private account PII (`account`) | `uid`, `email`, `createdAt`, `updatedAt` |
| `/usernames/{usernameLower}` | Unique lowercase username reservation | `uid`, `username`, `createdAt` |
| `/posts/{postId}` | Public posts & hashtags | `id`, `authorId`, `authorUsername`, `authorName`, `authorAvatarUrl`, `content`, `imageUrl`, `hashtags`, `visibility`, `isDemo`, `likesCount`, `commentsCount`, `createdAt`, `updatedAt` |
| `/stories/{storyId}` | 24-hour expiring stories | `id`, `authorId`, `authorUsername`, `authorName`, `authorAvatarUrl`, `mediaUrl`, `caption`, `isPublic`, `isDemo`, `viewsCount`, `createdAt`, `expiresAt` |
| `/stories/{storyId}/views/{viewerId}` | Story viewer receipts | `viewerId`, `viewerUsername`, `viewerName`, `viewerAvatarUrl`, `viewedAt` |
| `/bookmarks/{userId}_{postId}` | Private user post bookmarks | `userId`, `postId`, `postAuthorId`, `createdAt` |
| `/likes/{postId}_{userId}` | Deterministic post likes (prevents duplicates) | `postId`, `userId`, `postAuthorId`, `createdAt` |
| `/comments/{commentId}` | Post comments | `id`, `postId`, `postAuthorId`, `authorId`, `content`, `isPublic`, `createdAt`, `updatedAt` |
| `/followers/{followerId}_{followingId}` | Deterministic follow edges | `followerId`, `followingId`, `isPublic`, `createdAt` |
| `/notifications/{notificationId}` | Activity notifications | `id`, `recipientId`, `actorId`, `type`, `postId`, `message`, `read`, `createdAt`, `updatedAt` |
| `/conversations/{conversationId}` | Private 1-to-1 conversation headers | `id`, `participantIds` (size 2), `lastMessage`, `lastSenderId`, `lastMessageAt`, `createdAt`, `updatedAt` |
| `/messages/{messageId}` | Direct messages inside conversations | `id`, `conversationId`, `senderId`, `receiverId`, `participantIds`, `content`, `read`, `createdAt` |

## Firestore Security Rules Summary

Rules in `firestore.rules` enforce:
- **Default Deny**: Global catch-all denies all unspecified paths.
- **Email Verification**: Standard write operations require `request.auth != null && request.auth.token.email_verified == true`.
- **PII Isolation**: Only the owner can read or write `/users/{userId}/private/account`.
- **Strict Ownership**: Users can only edit their own profile, edit/delete their own posts and comments, and create/delete their own likes and follow edges.
- **Atomic Counters**: Updating `posts.likesCount` and `users.followersCount` requires atomic `existsAfter()` verification against `/likes` and `/followers`.
- **Private Messaging**: Only UIDs in `participantIds` (`size == 2`) can read, list, or send messages in a conversation.
- **No Unvalidated Fields**: Every `create` validates exact allowed keys (`hasAll` + `hasOnly`), string lengths, and server timestamps (`request.time`).

> **Note**: Always review and test `firestore.rules` against your project's threat model before sharing broadly.

- [ ] **Profile Management**: Upload profile picture and cover image, update full name, bio, and location, reload page to confirm Firestore persistence.

## User Guide

1. **Sign In**: Use **Continue with Google** for instant access or register with **Email and Password** (requires email verification).
2. **Create Posts**: Use the composer at the top of **Home** to publish text updates or attach images (JPEG, PNG, WebP, GIF up to 5 MB).
3. **Interact**: Click the heart icon to like posts, click **View thread** or the comment icon to read and write replies, and click any author's name to visit their profile.
4. **Discover People**: Open **Discover** to search members by name or `@username`, explore suggested accounts, and view popular discussions.
5. **Stay Updated**: Check **Notifications** for new followers, likes, comments, and incoming messages.
6. **Direct Message**: Open **Messages** (or click **Message** on any user's profile) to start a private 1-to-1 chat.
